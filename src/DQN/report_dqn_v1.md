## DQN Kaggle 제출 개선 보고서 (v1)_2025_11_21

### 1. 현재 구조 요약
- `DQN.py`는 학습 유틸(`train_dqn`, `ConnectFourTrainer`)과 제출용 `my_agent`가 함께 포함된 단일 파일 구조다.
- Kaggle에서는 외부 가중치를 읽지 못하므로, 학습이 끝난 뒤 `export_state_dict_literal` 결과를 `EMBEDDED_STATE_DICT`에 직접 붙여넣어야 한다.
- Kaggle 환경에는 PyTorch가 없기 때문에, 추론은 `EmbeddedPolicy` 라는 NumPy 기반 CNN 구현으로 수행된다.
- 학습 가중치가 없을 경우 `my_agent`는 `fallback_move`(센터 열 우선, 실패 시 랜덤)만 사용한다.

### 2. 관찰된 문제
- 시뮬레이션을 보면 초반에 새 컬럼을 적극적으로 개척하지 않고 중앙 또는 이미 사용한 열만 반복한다.
- 이유:
  1. **Fallback 로직** (`DQN.py:108-115`)이 센터 열만 선호해서, 학습 가중치가 없을 때 동일 행동이 반복된다.
  2. **학습 보상** (`ConnectFourTrainer._reward`)에서 “새 열 선호” 같은 보조 보상이 없기 때문에, DQN이 중앙 고정 습관을 학습했을 가능성이 높다.
  3. Kaggle 제출 파일에서는 규칙 기반 후처리가 없어서, CNN이 출력한 Q값 그대로 행동한다.

### 3. 성능 개선 전략
1. **Fallback 개선**
   - `fallback_move` 내에서 `playable`을 전체 순회하면서 “가장 낮은 높이”, “가장 왼쪽/오른쪽 미사용 열” 등 다른 기준을 적용한다.
   - 예: 아직 한 돌도 놓지 않은 열을 `playable`에서 우선 추출 후, 없으면 센터/랜덤.

2. **보상 설계 조정**
   - `ConnectFourTrainer._reward` 또는 학습 루프에서 “새 컬럼에 첫 착수 시 +α” 같은 shaping을 넣을 수 있다.
   - 반대로 오래 쌓인 열을 이용할 때는 작은 패널티를 주어 다양성을 장려한다.
   - 학습된 가중치가 이 규칙을 반영하게 되면, Kaggle에서도 일관된 행동을 얻을 수 있다.

3. **정책 후처리**
   - `EmbeddedPolicy.act` 호출 뒤에, 특정 상황(초반, 상대가 중앙을 선점했을 때 등)에서 우선순위를 재조정하는 간단한 룰을 섞는 방법도 있다.
   - 예: 초반 몇 턴 동안은 CNN Q값 대신 휴리스틱을 혼합해 새로운 열 탐색 확률을 높인다.

### 4. 다음 단계 제안
1. `fallback_move`를 개선(예: 새 열 우선)한 뒤 Kaggle 제출 테스트로 행동 변화 확인.
2. `ConnectFourTrainer._reward`에 보상 shaping(새 열 +0.05 등)을 추가해 다시 학습 후 가중치 내장.
3. 필요하면 `policy.act` 단계에서 초반 턴에만 가벼운 후처리(새 열 우선) 로직을 넣어 일관된 행동을 강제.

이 순서대로 적용하면, 휴리스틱·학습·정책 모두에서 “새로운 컬럼을 시도하는” 행동을 강화할 수 있다.
